# 领域引擎架构与 ADR

**ADR-01，建议 C，原生编排加进程内独立 Go 模块。** 首版与现有 server 一起发布。面向 PostgreSQL + Redis 的标准部署，启用按 KB 控制。上传由 WeKnora 负责。Go 在解析与切片之间提交领域快照，随后原生切片与领域任务分别推进。模板编译、阶段执行、证据、投影与查询集中在拟新增的 `internal/domainengine/`，只通过窄端口访问原生模型、存储、队列及索引。参见 [源码审计](SOURCE_AUDIT.md)。

| 方案 | 开发与维护 | 性能与部署 | 升级成本 |
| --- | --- | --- | --- |
| A，直接在原生服务串联专业阶段 | 接入最快，状态、业务规则与大型服务耦合 | 解析可复用，串联会让慢模型阻塞原生 worker 和 READY | 重解析、Wiki 所有权及失败语义变更时广泛冲突 |
| B，独立服务加公开 API | 需要会话代理、持久协调、访问校验、模型绑定和数据同步 | 双进程、跨服务搬运，公开接口缺完整解析快照，需重解析或新增契约 | 对原生实现变化较隔离，仍需维护解析与索引契约 |
| C，进程内模块加薄集成 | 共享既有基础设施。主要工作是快照/事务边界、权限、队列和索引适配 | 一次解析，原生与专业吞吐隔离，部署拓扑维持。长模型调用使用专用队列 | 接触少数源码点，有明确升级回归测试；未来可替换适配器独立部署 |

**ADR-02，完整原件和阶段产物。** 原文件以不可变快照保留，原生可见性与领域修订指针分别管理。专业产物为附加数据，支持追踪来源及回滚。删除、租户清退与法律/隐私政策走明确保留机制，不能通过默认日志清理删除。默认普通用户只能看到激活且当前授权的版本。

**ADR-03，模型负责语义，程序负责约束。** 模型负责科学理解、证据解释、术语匹配建议和不确定性。程序负责校验 Schema、局部 ID、引用、输入完整性、授权、映射、预先配置的数值转换及版本切换。日常走原生 `ModelService.GetChatModel` 和非流式 `chat.Chat`。独立绑定 Flow 1、Flow 2，读取内容、终止原因与 Usage。优先使用经实际端点验证的 JSON 输出能力，否则文本 JSON + 严格解析 + 有界修复。默认禁用工具、外部 URL 获取和推理轨迹保留。嵌入和重排单独使用 KB 模型。若账户能力、预算或数据出境政策未明确，保持停用并显示原因。

**ADR-04，知识投影。** 映射把记录与来源引用编译成确定性 Markdown，通过原生索引路径投送到受管派生 KB。原文 KB 是权限主体，派生文本的授权以原文实时授权为上限；首版禁止直接共享或通过原生未过滤的全局搜索暴露派生 KB，越权门未证实前禁用派生索引，Explorer 保持可用。派生 KB 禁止触发领域流水线，禁用 Wiki/图自动富化。检索融合按原文 ID + 证据/主张去重。结构化精确统计直接查询激活记录，图视图读取专业边，Agent 只调用类型化只读工具。默认不修改原生 Neo4j。未来接入受支持且可授权的图接口需要独立 ADR。

**ADR-05，模板是可审计程序输入。** 领域包含 manifest、原件指纹/原件、运行 Prompt、两个正式 Schema、记录/证据/关系/检索/界面映射、分类与约束，且可省略图映射。Schema 采用 Draft 2020-12，限定离线引用、长度、递归与复杂度。以 JSON Pointer 与受限数组遍历执行声明式规则，禁止执行任意代码、SQL 或网络调用。汽车模板和化妆品模板共用编译器和执行器，字段名只出现在配置与 fixture。

## 已批准的实施边界

采用 ADR-01。配置由顺序 Stage Definition 描述，每阶段声明输入、Prompt、Schema、模型引用和上游输出依赖。可选阶段能独立产出制品，执行层不得把阶段数量固定为二。模板编辑支持 Prompt、Schema、分类与映射。配置草案生成保留端口，Phase 2A 不调用 AI。

记录、检索和图谱各自发布就绪状态。有效结构化记录可先于索引与图使用。Agent 的验收同时覆盖原文召回、专业语义召回与精确查询，并在三种来源上执行相同的版本和撤权检查。授权删除和隐私政策优先于历史保留。

## Phase 2B 执行

同一个 server 内新增专用 Asynq 领域队列与小型 worker 池，仍使用既有 Redis 和模型限流器。持久任务行的到期字段承担事务 outbox。Redis 消息可重建，领域状态与原生入库状态分开。权限撤销时用 access epoch 使旧作业和制品不可读，源生命周期变更与清理在 PostgreSQL 同一事务执行。模型调用前再次检查授权及 fence。

### Phase 2B.1 审核加固

同进程架构保持不变。阶段预算从原生模型能力与已发布阶段配置计算，调度使用心跳维护短租约。专业上传先落库提交意图，原生文件行提交后才可调度；丢失唤醒由持久意图恢复。重跑的创建、产物复用和排队在同一事务，使用原生文件身份与当前授权锁保护提交。
