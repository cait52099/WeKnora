# 自动入库及恢复设计

1. 用户在已绑定 KB 使用原生上传。领域适配器在受权创建路径捕获预期内容版本、绑定版本及模型配置指纹。原件在 native delete/reparse 之外保留持久引用或按内容寻址复制，确认存储之后才可进入解析快照就绪。首版自动触发文件上传和显式重解析，URL、手工录入及连接器走原生能力，按独立用例扩展。
2. 原生 `ProcessDocument` 解析一次，在构建来源索引后提交快照。快照以 doc/content/parser fingerprint 定位，包含原始及规范化文本、图片和可用来源位置。写对象后在事务内确认源版本，登记 artifact、job 和 outbox。领域故障不得使原生索引失败；保存可恢复的捕获失败状态，自动重试，快照丢失时通过受保护的原生重解析恢复并显式记录重新解析原因。初始化阶段对持久记录与队列缺口进行 reconciliation。
3. **Flow 1** 使用快照和明确随文上传的补充材料，按模型实际 token 预算决定全文或按章节/实验分片。分片带原位置、输入覆盖清单和有界合并任务，复查冲突与缺失；不能静默截断。不支持的图片/表格显式警告；合并输出仍通过整份 Schema。
4. **Flow 2** 默认只读取已验证的完整 Flow 1 JSON，保留 paper_id 与 analysis_json_only。超预算时标记等待处理，不能静默只取前段；可另立经审核的分区输入契约。原文复核由可选 Evidence Audit 产生单独制品和来源标记。两阶段各用独立固定模型配置，关闭工具。
5. 按版本执行确定性验证与投影。保存原响应内容、拒绝原因及每次修复尝试，默认排除认证信息、隐藏推理和提供商原始请求头。解析阶段拒绝歧义重复键、额外文本及错误返回形状；报告 Schema JSON Pointer。语义校验检查当前制品 ID、来源路径解析与必要证据。高影响歧义入审核，非关键缺失附质量标记。
6. 术语协调生成候选和任务，绑定已确认结论或显示未审核。先写未激活 generation 与 index_links，确认全部必需索引就绪，再以源修订及绑定版本 CAS 切换 active_generation。搜索和 Agent 都要过滤未激活派生结果；与外部索引无法跨事务，切换前后允许保守漏召而禁止访问过期数据。旧 generation 保留且从活跃查询撤回。无图映射时可正常索引。

领域状态为 `queued → running → succeeded`，每阶段另有 `retry_wait / failed / cancelled / needs_review`。任务首页可合并展示 `waiting_parse / extracting / analyzing / validating / projecting / indexing / ready`；科学 JSON 的 `analysis_status`、`semantic_status` 与原生 ParseStatus 保持独立。质量状态另显示，支持完成但待审核。默认必需记录和索引失败阻止激活旧版本替换。

Asynq 仅传 ID，DB 以 stage_key（作用域、源修订、阶段、配置与依赖哈希）为幂等键，attempt 单列记录。专用队列从 DB claim 可到期租约并续期，单次提交同时检查 token、取消状态和源版本。worker 复查模型引用和租户/KB；密钥轮转允许重新解析引用，模型行为配置变化须显式新运行。事务内保存阶段结果和后继 outbox。清扫器重新派发丢失唤醒、租约过期和到期重试。限额按租户和模型，包含并发、请求速率、token 与费用预算；429 按 Retry-After 加抖动，超时/5xx 有界指数退避，403/不兼容配置需修正，格式错误只允许有限修复。外部调用丢响应可能产生重复计费，按提供商请求 ID 和不确定状态记录。取消后在模型返回和索引激活时再次检查，晚到结果可归档而不得激活。

重跑计划显示代价与受影响版本。解析变动重跑全部，Flow 1 变动重跑下游，Flow 2 兼容变动复用 Flow 1，映射变动只重投影，嵌入变动只重索引。删除源触发撤回且不得被旧 worker 恢复；暂时取消专业任务不删除原生文档。日志保留阶段、错误码、耗时、输入覆盖、token 及 trace ID，正文和凭据不进通用日志。

## 中断与重跑的并发约定

暂停是 job 控制状态，停止领取后续阶段。已领取的阶段在租约期内可提交不可变制品，但暂停期间不激活 generation。恢复时只有当前源和授权仍有效才能派发。取消是终态，立即使现有租约失效。用户可从上一个有效 checkpoint 创建新的显式运行。重试命令限于同一已固定配置，配置变更走重跑预览。源上传、解析或绑定并发更新时，以数据库中通过 CAS 接受的源修订与发起意图为准；较晚返回的旧模型结果不具备激活资格。

发布阶段横跨对象存储和数据库。对象写入按 hash 可重试，DB 未登记的临时对象经恢复扫描后按租户保留策略清理。每个外部索引写入使用确定的逻辑 key，首次回执未知时先对账，避免重复创建。激活事务更新 DB 指针，清扫器随后清理不可达派生索引。索引失败继续服务现有已授权的激活版本，作业可从已验证记录重新投影。
